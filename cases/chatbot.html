заявка не потеряется в сообщениях

Собственный Telegram-канал для обращений: клиент пишет боту, система регистрирует заявку и передаёт сообщение владельцу. Ответ владельца передаётся через бота в тот же чат без раскрытия личного Telegram-аккаунта.

Задача

Нужен простой вход для потенциального заказчика: не публиковать личный номер и профиль, не заставлять человека заполнять сложную форму, сохранять связь по каждой заявке и отвечать в привычном Telegram. При этом отдельная CRM и второй номер телефона не требуются.

Схема решения

Сайт-портфолио → Telegram-бот → SQLite: заявка → Уведомление владельцу → Ответ в чат клиента
  • Клиент отправляет описание задачи и при необходимости поддерживаемое Telegram-вложение.
  • Python-сервис присваивает обращению номер, учитывает открытые и закрытые заявки, сохраняет служебные идентификаторы для маршрутизации.
  • Владелец получает уведомление и отвечает обычным Reply на сообщение заявки. Ответ передаётся через бота.
  • Поддерживаются статистика /stats, закрытие /close, блокировка спамера /block и открытие нового обращения /new для клиента.

Почему решение не перегружено

Сервис написан на Python и работает с Telegram Bot API по long polling. Для приёма сообщений не нужен публичный HTTP-порт или отдельный веб-сервер. SQLite хранит состояние заявок и служебную маршрутизацию, не сохраняя текст клиентской переписки в собственной базе. Вложения пересылаются средствами Telegram без обязательного скачивания на VPS.

Бот не генерирует ответы нейросетью: он принимает и маршрутизирует обращения, а на вопросы отвечает человек.

16 ноября 2026 года на Linux VPS включена отдельная служба systemd с автоматическим запуском и перезапуском при сбоях. Проверены запуск бота, подключение Telegram, настройка владельца и выполнение команды статистики. Служба изолирована от других проектов сервера.

Граница проверки: обмен сообщениями с независимым клиентским аккаунтом, вложения и ответы владельца в реальном диалоге ещё предстоит проверить. До завершения проверки статус проекта — тестовая эксплуатация.

Что показывает проект

Проект охватывает требования к приёму заявок, маршрутизацию сообщений, контроль доступа, обработку ошибок, тестирование и развёртывание постоянной службы на сервере.

Подобная архитектура подходит для небольших команд, приёма первичных обращений, записи заявок и простых информационных маршрутов — когда тяжёлая CRM избыточна.

Технологии

Python 3.12 · Telegram Bot API · long polling · SQLite · Linux VPS · systemd · журналирование.

Статус: серверная служба запущена и отвечает на административные команды. Финальный внешний тест коммуникации запланирован.

Моя роль: формулирование сценария, требования, организация реализации, проверка работоспособности и развёртывание.

Безопасность: токен и ID владельца не опубликованы. Пожалуйста, не отправляйте через бота пароли и конфиденциальные документы.
